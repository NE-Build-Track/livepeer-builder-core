## 1. The container question: stay with Pure DI

`BuilderEngine.from_settings` (`src/livepeer_builder/runtime/engine.py:95-214`) is already a hand-written composition root. The skill says to adopt a container only when two or more of the following hold. Here, none clearly does:

| Trigger | This project |
|---|---|
| Many entry points sharing a graph | `lpb serve`, the CLI subcommands and the Railway entrypoint all share **one** root, `from_settings`. The graph is not duplicated |
| Several request-scoped resources with cleanup | None. Each repository method opens its own connection (`store/sql.py:76,83`); there is no session or unit of work per request |
| A graph too large to read in one root | About 20 objects in one 120-line function. Readable, though growing |
| Frequent per-environment swaps | Handled by settings plus ten keyword overrides |

**Recommendation:** add no container, either to the library (the skill forbids that) or to the server, where it would wrap a single `BuilderEngine`. If the `dependency-injection-refactor` branch is meant to adopt dishka or dependency-injector, redirect it to the structural fixes below.

**Reverse this if:** a unit of work or session starts spanning several repositories per request or job, or new process types (workers, schedulers) need different subgraphs of the engine.

## 2. Review

### Summary

The library side matches the skill's container-agnostic model unusually well:

- Protocol ports for every extension point;
- services that receive their collaborators;
- no module-level clients and no import-time I/O;
- explicit ownership flags and a list of resources to close on shutdown;
- framework code confined to `http/`, enforced by AST import tests;
- shipped fakes, with a "fakes, not mocks" policy.

The gaps are in the **second goal**, the reference server, and in how far customization reaches. Findings: **0 critical, 2 major, 6 minor.**

### [Major] The reference server does not model configuration or customization

- **Where:** `src/livepeer_builder/cli.py:147-163` (`lpb serve`) and `deploy/railway/engine/entrypoint.py:63-76`. Both call `create_app(await BuilderEngine.from_settings(settings))` with **no overrides**. The customization examples (custom authenticator, policy, secret store, selection, discovery wrapper) exist only as tests (`tests/unit/test_extension_examples.py:39-192`).
- **What happens:** a builder who wants the server with a custom authenticator or secret store finds no runnable root to copy. They can only use `LPB_*` variables, or reverse-engineer a test fixture. The server cannot be "a model on how to configure and customize the package" because the configuration it shows is environment-only.
- **Rule:** the reference application is the documented composition root. It shows customization through the root and uses only the public API.
- **Fix:** add one explicit server composition root, for example `livepeer_builder/http/main.py` or a `server.py` module:
  1. A `build_engine(settings, **overrides)` function that the CLI, the Railway entrypoint and the docs all call.
  2. One commented example that wraps a default (Decorate) and one that replaces a port (Replace), using the public API.
  3. A test that runs the same extension examples through that root.

  `create_app(engine)` already takes a pre-built engine, so this is additive. **Cost:** one module and a docs page; the extension examples get a second home.

### [Major] The facade is the only full composition root, and its override surface is incomplete

- **Where:** `engine.py:96-110` exposes ten overrides. These cannot be replaced through `from_settings`:
  - the operator `grants_client` (`:140-146`);
  - the always-appended `ApiKeyAuthenticator` (`:204`);
  - `ReservedEventFeed` and `ReservedSessions` (`:211-212`);
  - `StreamLimits` and `AdmissionLimiter` construction;
  - `CostSyncWorker` filters.

  The alternative is `BuilderEngine.__init__`, which takes concrete service types (`AuthenticatorChain`, `JobService`, …; `:60-77`). Using it means re-creating all of `from_settings` by hand.
- **What happens:** "Customize without forking" (core belief 5) holds only for the ten chosen ports. A consumer who needs a different grants manager, or wants API-key auth off, has to copy the wiring. Each new extension point adds another keyword to an already long signature.
- **Rule:** a facade gives a short path; it should not be the only path. Customization goes through ports, and consumers can supply any port.
- **Fix (skill pattern: defaults as data):**

  ```python
  @dataclass(frozen=True)
  class EngineParts:  # every replaceable port, nothing else
      store: EngineStore
      clock: Clock
      policy: AccessPolicy
      authenticators: tuple[Authenticator, ...]
      discovery_source: DiscoverySource
      transport: RunnerTransport
      selection: SelectionPolicy
      allocation_manager: AllocationManager | None
      grants_manager: AllocationManager | None
      usage_source: UsageSource | None
      secret_store: SecretStore
      events: EventFeed
      sessions: SessionManager


  async def default_parts(settings: EngineSettings, stack: AsyncExitStack) -> EngineParts: ...
  def assemble(
      settings: EngineSettings, parts: EngineParts, closers: AsyncExitStack
  ) -> BuilderEngine: ...  # no I/O


  # from_settings becomes: parts = await default_parts(...); parts = replace(parts, **overrides); return assemble(...)
  # a consumer:            parts = replace(await default_parts(settings, stack), transport=MyTransport())
  ```

  **Cost:** a new public type to version. The cheaper alternative is to add the missing keyword overrides and accept a longer signature. **Question:** is the always-on `ApiKeyAuthenticator` a policy decision? If so, document it as non-replaceable, the way the services are.

### [Minor] Partial construction leaks resources (verified)

- **Where:** `engine.py:120-133`. `SqlStore.connect` runs (and may migrate) before `EncryptedDbSecretStore` builds `Fernet(key)` in its constructor (`adapters/secrets.py:52-54`).
- **What happens:** probe result: with `secret_key="not-a-fernet-key"`, `from_settings` raised `ValueError: Fernet key must be 32 url-safe base64-encoded bytes`. The store it had connected was **never closed** (`stores created: 1 closed: 0`). The same applies to the Batteries clients if a later step fails. A CLI process exits anyway, but an embedding application or a test suite leaks connections.
- **Rule:** ownership is explicit; a factory that fails part-way closes what it opened.
- **Fix:** build into an `AsyncExitStack` and call `pop_all()` on success, handing the stack to the engine in place of the `closers` list. This also removes the `getattr(closer, "aclose") or getattr(closer, "close")` duck-typing in `stop()`. **Cost:** small.

### [Minor] The facade reads the environment implicitly

- **Where:** `engine.py:112`: `settings = settings or EngineSettings.from_env()`.
- **What happens:** an embedding application that calls `from_settings()` with no arguments silently reads `LPB_*` from its own process environment. That surprises tests and multi-tenant hosts. Every in-repo caller already passes settings explicitly (`cli.py:111,119,135,157`; the Railway entrypoint).
- **Rule:** the library receives a settings value. `from_env()` is fine as an explicit opt-in, never as a silent default.
- **Fix:** make `settings` required. **Cost:** a one-line change for callers that relied on the default.

### [Minor] The SDK adapter calls module-level third-party functions, so tests patch them

- **Where:** `adapters/sdk.py:69,135,168` call `livepeer_gateway` functions directly. Tests replace `sdk.call_runner` and `sdk.discover_runners` with `monkeypatch.setattr` at 14 sites (`tests/unit/test_adapters.py`, `test_adapter_edges.py`, `test_stream_deadlines.py`).
- **Rule:** inject the function rather than patch the import path; a function parameter is a dependency.
- **Fix:** add `call_runner: CallRunner = gateway.call_runner` (and the same for `discover_runners`) to the adapter constructors, typed with a `Protocol` or `Callable`. Tests pass a fake, and consumers can wrap it with retries or metrics. **Cost:** small; tests get simpler.

### [Minor] Tests are coupled to structure: private wiring asserts and patched live methods

- **Where:**
  - Wiring is asserted through private attributes: `engine.discovery._source`, `engine.payments._manager`, `engine.costs._worker._source`, `engine._tasks` (`tests/unit/test_runtime.py:83-127`).
  - Methods on live objects are patched, including `engine.jobs._store` (`test_service_edges.py:306`) and `store.finish_job` (`test_stream_lifecycle.py`).
  - A module constant is patched: `_OPEN_BACKSTOP_GRACE_S` (`test_stream_deadlines.py:57`).
- **What happens:** pure refactorings of the wiring, such as the `EngineParts` change above, will break these tests without any change in behaviour.
- **Rule:** assert outcomes through the public surface; composition tests check behaviour, not private attributes.
- **Fix:**
  - Assert wiring by behaviour: a fake that records it was used.
  - Move the backstop grace period into `StreamLimits`, which is already a parameter object.
  - Prefer a failing fake repository over patching methods on the real store.

  **Cost:** rewriting those tests.

### [Minor] The package root imports every default adapter's dependencies (verified)

- **Where:** `import livepeer_builder` loads `sqlalchemy`, `alembic`, `httpx`, `cryptography`, `livepeer_gateway` and `aiohttp`, because the root `__init__` exports `BuilderEngine`, which imports every default adapter. It imports no web framework and no container.
- **What happens:** a consumer who only wants the contracts, or who supplies their own store and transport, still installs and imports all of these. `aiohttp` is imported in `adapters/sdk.py:18` but not declared in `pyproject.toml`; it arrives only transitively through `livepeer-gateway`.
- **Rule:** a default that drags in a heavy dependency is a "foreign default".
- **Fix:**
  - Declare `aiohttp` explicitly.
  - Optionally import adapters lazily inside `default_parts` rather than at module level.

  Splitting the distribution was considered and rejected in the design record; that decision stands. **Cost:** small.

### [Minor] The deployed root configures by mutating `os.environ`

- **Where:** `deploy/railway/engine/entrypoint.py:79-83` rewrites `os.environ["LPB_DATABASE_URL"]` before `from_env`.
- **Rule:** configuration is a value built at the edge.
- **Fix:** `settings = EngineSettings.from_env().model_copy(update={"database_url": asyncpg_url(...)})`. The migrate path that shells out to `lpb` still needs the environment variable, so keep the rewrite there only. **Cost:** small.

### What is already right

- **No container** anywhere, and Pure DI wiring in one root. A container would add a dependency and buy little.
- **Ports:** every extension point is a `typing.Protocol` in one module (`protocols/__init__.py`). Services depend only on protocols, and the docs say so.
- **Constructors:** services take their collaborators and do no I/O. `SqlStore.connect` is a separate async factory.
- **Ownership:** `BatteriesClient` and `BatteriesUsageSource` track `_owns_client` and close only clients they created. The engine closes only what `from_settings` built, never caller-supplied overrides.
- **No ambient state:** no module-level clients, no `lru_cache`, no `global`, no import-time environment reads.
- **Settings:** a frozen pydantic model; services receive values, not the settings object.
- **Logging:** configured only at application edges (`cli.py`, the Railway entrypoint).
- **Framework confinement:** FastAPI and Starlette appear only in `http/`, enforced by `tests/structure/test_layers.py`. `create_app(engine)` takes a pre-built engine. `Depends` is used once, as a thin auth adapter. `manage_lifecycle=False` lets tests own the lifecycle.
- **Tests:** shipped fakes in `livepeer_builder.testing`; no `unittest.mock`; real SQLite for persistence; `httpx.MockTransport` injected through the adapters' `client=` parameter.
- **Server in the same wheel behind `[server]`:** acceptable under the skill's tradeoffs (a small server, the same release cadence), because the layer test removes the main risk of importing internals.

### Questions

1. Is the always-appended `ApiKeyAuthenticator` deliberate policy, or an extension point that has not been exposed yet?
2. Should the grants manager be replaceable separately from the allocation manager?
3. Is `BuilderEngine.__init__` meant to be public? It is undocumented as an extension path, and it takes concrete service types.
