# M3 decisions

Accepted decisions after the M2 close-out ([m2-decisions](m2-decisions.md) holds D1–D28).

| # | Decision | Where |
| --- | --- | --- |
| D29 | **Streaming is generic and per job** (Mike, 19 October, from the first enterprise reference app's requirement). `jobs.stream` delivers one runner response as bytes plus a content type; the engine never interprets the stream. `mode` stays `immediate`; async (M4) is untouched | [engine.md#streaming](../contracts/engine.md#streaming), [plan](../exec-plans/active/streaming-jobs.md) |
| D30 | **A stream the caller stops reading is `abandoned`, and the job `uncertain`** when payment went out (Mike, 19 October). The work was paid for and probably ran; the engine never pretends otherwise. `abandoned` is both an attempt outcome and a failure kind | [engine.md#streaming](../contracts/engine.md#streaming) |
| D31 | **Payment evidence is written before the first byte** of a stream, on the `in_flight` attempt, so a restart mid-stream resolves the job as `uncertain` (Mike, 19 October) | `services/jobs.py` |
| D32 | **`Runner` carries `version`, `metadata` and `gpu` as the node echoes them** (Mike, 19 October). The engine never interprets `metadata`; the chat runner publishes `{"model_id": …, "max_context": 131072}` there and ChatLPT reads it instead of paying for a models call | [engine.md#discovery](../contracts/engine.md#discovery) |
| D33 | **Streaming is optional for transports**: `StreamingRunnerTransport` adds `open`; a transport without it makes `jobs.stream` answer 400 rather than changing the `RunnerTransport` protocol every integrator implemented (Mike, 19 October) | `protocols/__init__.py` |
| D34 | **A stream's end is recorded by a task the caller cannot cancel** (Mike, 20 October). A client disconnect under Starlette/anyio cancels every await in the request task, so the job, attempt and slot are finished in their own task. The admission slot is always released; the writes are bounded by `LPB_STREAM_FINALIZE_TIMEOUT_S` (default 10 s), and a store failure leaves the job `running` for `recover_interrupted` | `services/streams.py`, `utils.run_shielded` |
| D35 | **Stream deadlines** (Mike, 20 October): `timeout_s` counts from the job's start and covers opening; `first_byte_timeout_s` (default 60 s, capped at `timeout_s`) bounds each runner request to its first chunk; `idle_timeout_s` now defaults to 60 s. First-byte and idle count only while the caller waits. A timeout never fails over. The transport enforces the first-byte limit and keeps the signed sessions; the engine stops a transport 5 s past it and treats the payment as sent | [engine.md#deadlines-d35](../contracts/engine.md#deadlines-d35) |
| D36 | **The engine owns open streams** (Mike, 20 October): `JobStream` is an async context manager; `engine.stop()` waits `LPB_STREAM_DRAIN_TIMEOUT_S` (default 30 s) for open streams and then abandons the rest; `timeout_s` ends a stream nobody reads; a failed write right after `open` closes the stream and keeps its manifests | [engine.md#how-a-stream-ends](../contracts/engine.md#how-a-stream-ends) |
| D37 | **REST streams fail visibly** (Mike, 20 October): the response headers wait for the runner's first chunk, so earlier failures use the ordinary mapping (504, 502); a failure after it aborts the connection instead of ending the body cleanly. The engine never writes into the stream (D29) | [engine.md#rest-d37](../contracts/engine.md#rest-d37), `http/streaming.py` |
| D38 | **"Done" comes from the caller or the runner, never from parsing** (Mike, 20 October): `JobStream.complete()` records `succeeded` with the bytes received; a cancelled reader or disconnected client gives the runner `LPB_STREAM_SETTLE_S` (default 1 s) to end the stream, else `abandoned`; `aclose()` stops at once | [engine.md#how-a-stream-ends](../contracts/engine.md#how-a-stream-ends) |
| D39 | **Signed-session rows are append-only** (Mike, 20 October): `finish_attempt` adds manifests not stored yet and never rewrites a row, because cost sync owns the match columns. A stream writes its sessions twice (D31 and at the end) and must not reset a match made in between | `store/sql.py`, `protocols.JobRepo.finish_attempt` |
